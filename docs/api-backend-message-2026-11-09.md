확인한 주소는 아래와 같습니다. 11월 9일 21:29에 Swagger가 직접 불러오는 명세를 다시 받아 확인했습니다.

전체 알림 조회·읽음, 회원 탈퇴, 선택한 LITE/PRO 플랜 변경 요청, 사진 cursor 추가 조회는 기존 API로 프론트 연동했습니다. 모의 API 검증은 완료했으며 실제 계정 탈퇴·결제는 실행하지 않았습니다.

1. **템플릿 저장/조회 확인**
   전에 작업 중이라고 들었던 템플릿 저장이 반영됐는지 확인 부탁드립니다. 프론트는 방 PATCH에 scrollTemplateId를 보내고 방 조회에서 같은 값을 사용하지만, 현재 공개 명세에는 해당 필드가 없습니다. 이미 구현됐다면 요청/응답·허용값·방장/플랜 권한을 명세에 반영 부탁드립니다.

2. **알림 삭제 기능 추가 요청 — 테스터 피드백**
   테스트 중 ‘받은 알림을 직접 삭제하고 싶다’는 의견이 있어 새로 추가된 요구사항입니다. 기존 알림 기능 오류를 의미하는 것은 아닙니다. 현재 프론트는 이 기기에서 숨기기만 제공하므로, 본인 알림을 서버에서 삭제하고 전체/방별 목록과 읽지 않은 수에 반영하는 API가 필요합니다. 예: DELETE /notifications/{notificationId}.

3. **웹 푸시 API 확인**
   프론트가 사용하는 GET /push/vapid-public-key, POST/DELETE /push/subscriptions가 공개 명세에는 없습니다. 구현돼 있다면 명세와 payload를 공유 부탁드립니다. 미구현이면 등록·해제와 실제 푸시 발송 연결이 필요합니다.

4. **사진 처리 완료 계약 확인**
   POST /photos/{photoId}/complete 응답의 photo.status와 PROCESSING → READY/FAILED 전이를 명시해 주세요. 같은 complete를 반복 호출해 상태를 확인해도 되는지, 별도 조회 API를 써야 하는지 확인 부탁드립니다.

5. **동의 버전 조회 확인**
   GET /consents/current가 구현돼 있는지 확인 부탁드립니다. 현재 명세에 없고, 프론트는 조회 실패 시 v1을 사용합니다.

추가 개선 요청으로, 방 생성/유료 방 주문 입력에 deadlineAt을 함께 저장할 수 있으면 좋겠습니다. 지금은 생성·결제 승인 후 별도 PATCH를 보내므로 예약 저장이 누락될 가능성이 있습니다.

또한 Swagger 명세의 servers.url이 아직 https://api.example.com/api/v1로 되어 있습니다. 실제 API Base URL로 수정 부탁드립니다.

구현 여부를 확인한 뒤 없는 기능만 추가하고, 이미 있는 기능은 명세를 갱신해 주시면 됩니다. 세부 프론트 연동 결과와 조건부 개선안은 첨부한 api-audit-2026-11-09.md에 정리했습니다.
