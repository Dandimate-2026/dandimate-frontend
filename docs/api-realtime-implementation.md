# 질문·답가·결제 복구 및 실시간 갱신

## 화면에서 달라지는 점

- 방 홈 상단 ‘내 질문’에서 답할 질문·전체 질문을 확인합니다. 다음 질문 조회 API의 남은 개수를 표시하고, 질문을 건너뛰거나 답변하면 다음 질문으로 이동합니다. 모두 마치면 완료 화면을 보여 줍니다.
- 질문을 처리한 후 다음 질문 조회가 실패해도 입력을 다시 제출하지 않습니다. 처리 완료 화면에서 다음 질문만 다시 조회합니다. 질문 ID가 바뀌면 녹음·입력 상태를 초기화합니다.
- 두루마리의 내가 쓴 답가에만 삭제 버튼을 표시합니다. 확인 후 DELETE 요청을 보내고, 반환된 작업의 완료를 확인하여 문단과 답가 목록을 다시 읽습니다. 실패하면 오류를 표시합니다.
- 방장에게 ‘지금 마감하고 두루마리 엮기’를 제공합니다. 사진 수집·돌려보기 상태에서만 보이며 확인 후 EARLY 모드로 마감하고 작업 화면으로 이동합니다.
- 질문 분석 실행은 서버 명세의 데모 전용 기능입니다. 개발 모드의 방장 질문 목록에서만 ‘데모 질문 생성’을 제공하며 생성 작업이 끝난 뒤 목록을 갱신합니다.
- 결제 복귀 시 주문을 먼저 조회합니다. DONE이면 재승인하지 않고 완료 화면으로 복구하고, PROCESSING이면 조회로 확인합니다. READY 주문은 성공 복귀의 승인 정보와 서버 주문 금액이 맞는 경우에만 승인합니다. 조회로 확정하지 못한 결과는 성공·실패로 단정하지 않습니다. 크레딧 주문은 서버 orderType도 확인합니다.

## 실시간 갱신

- 알림 목록·질문 목록·질문 상세·돌려보기·두루마리에 SSE 갱신을 연결했습니다.
- photo.deleted, entry.updated, entry.deleted, scroll.template.updated 이벤트를 추가했습니다.
- 연결 실패 시 전경에서 2초마다 조회하고, 10초마다 새 일회용 토큰으로 재연결을 시도합니다. 연결 성공 시 폴링을 중지하고 한 번 갱신합니다. 화면 복귀 시에도 갱신합니다.
- 기존 푸시 구독은 서버에 다시 등록한 후에만 켜진 상태로 판단합니다. 서버 등록 실패 시 브라우저 구독이 존재한다는 이유만으로 성공 처리하지 않습니다.

## 연결한 API

- GET /rooms/{roomId}/askbacks/next
- POST /askbacks/{askbackId}/pass
- GET /rooms/{roomId}/askbacks/me
- POST /rooms/{roomId}/askbacks/run (개발·데모 전용)
- DELETE /replies/{replyId}
- GET /payments/orders/{orderId}
- POST /rooms/{roomId}/close

## 검증

- `node --test tests/kakaoShare.test.cjs tests/realtime.test.cjs tests/paymentRecovery.test.cjs`: 32개 통과
- 수정한 실행 코드·테스트 파일 ESLint 및 TypeScript 검사 통과
- API 응답을 가로챈 실제 Chromium 화면 흐름 5개 통과: 질문 전환·완료, SSE 알림 표시, 답가 삭제 및 다른 답가 보존, 조기 마감, 완료 크레딧 주문 재승인 없이 복구. 페이지 오류 없음
- 위 브라우저 테스트는 운영 서버의 데이터를 변경하거나 실제 결제를 요청하지 않습니다.

실제 계정 간 SSE 발행·수신, 카카오 로그인된 기기에서의 웹 푸시 수신, 서버의 데모 실행 허용 여부와 결제 테스트 상점 연동은 별도 확인이 필요합니다. 푸시·약관 조회 API가 공개 명세에 없는 문제는 백엔드 문서 보완이 필요합니다.
