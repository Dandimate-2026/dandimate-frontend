# iOS 테스트 수정 및 검증 기록 — 2026-11-09

## 반영한 변경

| 항목 | 반영 내용 / 남은 확인 |
| --- | --- |
| 1. 여러 날짜 모임 | 현재 공개 API는 `meetingDate` 한 개만 지원한다. 생성·설정에서 “모임 시작일”로 표시하고 여러 날의 모임은 첫날을 선택하도록 안내한다. 종료일 저장은 백엔드 필드가 필요하다. 사진을 모임 날짜와 대조해 제한하지 않는다. |
| 2. 내 덧붙임 중복 | 서버 이야기와 로컬 저장 직후 미리보기를 중복 렌더링하지 않는다. 같은 entry ID도 중복 제거한다. 내 첫 한마디와 내 덧붙임의 제목을 구분한다. |
| 3·6·9. 알림 | 새 명세의 `PHOTO_ADDON_ADDED`, `HOST_TRANSFERRED`, `ROOM_PLAN_UPGRADED`를 타입·문구·이동 경로에 반영했다. PHOTO 리소스는 해당 사진, 다른 리소스는 사진 목록으로 연결한다. 실제 서버 알림 생성·기기 푸시 도착은 미검증이다. |
| 4. 첫 두루마리 날 | 방장이 정하지 않은 기본 마감일은 확정 날짜처럼 표시하지 않는다. 미설정 안내와 날짜의 의미를 표시하고, 저장 후 `deadlineChangedByHost` 상태를 갱신한다. |
| 5. 날짜 UI 넘침 | iOS 날짜 입력의 최소 폭과 최대 폭을 제한하고 다이얼로그의 세로 스크롤을 허용한다. |
| 7. 선택한 사진 대신 내 사진 | 일반 진입은 목록으로 시작한다. 사진을 지정하면 해당 사진을 연다. 없는 사진은 다른 첫 사진으로 대체하지 않고 목록과 안내를 보여준다. |
| 8. 추가 업로드 | 방 홈에 잔여 한도가 있으면 “사진 추가하기”를 표시한다. 친구를 기다리는 모으기 화면에서도 첫 한마디 완료 여부와 무관하게 추가 업로드할 수 있다. |
| 10·12. 플랜 변경 및 중복 결제 | 설정에 현재 플랜·변경 버튼 추가. 현재 플랜과 하위 플랜의 선택·결제를 차단한다. 주문 직전 서버 방 정보를 다시 읽어 방장 권한과 플랜을 검사한다. 동시 결제에 대한 최종 차단은 서버가 담당한다. |
| 11. 엮기 전 확인 | 지금 엮기 확인창과 예약 날짜 설정에 현재 플랜을 표시한다. 지금 엮기 확인창에서 플랜 변경 화면으로 갈 수 있다. |
| 13. 지도 집계 | API에서 `recordCount`는 첫 한마디·덧붙임·되묻기 답의 합이다. 사진 1장에 이야기 2개가 있을 수 있다. 도시 요약을 사진 수·이야기 수·모임방 수로 구분했다. 실제 문경 계정 데이터는 확인하지 않았다. |
| 14·15. 친구 사진 목록 | 뒤로가기 있는 사진 목록을 추가했다. 위치 없는 사진도 표시하고, 올린 본인은 장소를 추가·변경할 수 있다. 선택한 사진 안에서는 덧붙이기·다음 사진 버튼을 유지한다. |
| 16. 하단 겹침 | 첫 한마디 화면의 고정 높이를 제거하고 콘텐츠 높이로 늘어나게 했다. 하단 안전 영역 여백을 적용하고 사진 상세 액션은 흐름 내 sticky footer로 둔다. |
| 17. 작성 취소 | 선택한 파일·장소·녹음은 확정 전까지 로컬 상태로 유지한다. 글 확정 또는 명시적인 “나중에”에서 업로드한다. 음성은 로컬 미리듣기 뒤 “확정하고 사진 올리기”에서 업로드·받아쓰기·첫 한마디 저장을 진행한다. 받아쓴 글 수정은 업로드 후 내 이야기 고치기를 사용한다. 실패·이탈 시 미확정 서버 사진을 정리하고 중복 제출을 막는다. 앱 강제 종료 중 서버 쓰기까지 원자적으로 취소하는 것은 별도 서버 초안/게시 트랜잭션이 필요하다. |
| 방 설정 장소·추천 | 모임 장소 입력란과 관련 편집 동작을 제거했다. 템플릿 선택의 장소·방 이름 기반 자동 추천·자동 선택도 제거했다. |

## 새 API

[공개 명세](https://43-201-73-60.sslip.io/openapi/public-api.yaml)를 받아 확인했다. 신규 전체 방 알림 조회 `GET /notifications`를 `getAllNotifications`로 추가했다. Photo의 nullable `location` 필드와 새 알림 세 종류를 반영했다. 푸시 구독·VAPID API는 이 명세에 없어 서버 발송 계약은 별도로 확인해야 한다.

## PWA 링크

- manifest의 `id`, `start_url`, `scope`는 `/`로 `/invite/{token}`을 포함한다. `launch_handler.client_mode: navigate-existing`를 추가했다. 이 값은 지원 브라우저의 실행 창 선택을 정하며 외부 링크 캡처를 강제하지 않는다.
- 프로덕션 공유 URL은 `VITE_SITE_URL`이 있으면 그 값을, 없으면 현재 origin을 사용한다. 설치 앱과 초대 링크의 scheme·host·port가 같아야 한다. 로컬 개발의 기본 공유 주소는 기존 배포 주소를 유지한다.
- 서비스 워커는 초대 경로에 SPA 내비게이션 fallback을 적용한다. 최초 온라인 방문의 직접 URL 처리는 호스팅 서버도 `index.html` fallback을 제공해야 한다.
- 카카오톡 인앱 브라우저에는 기본 브라우저로 열기 안내를 제공한다. 자동 실행이 안 되면 링크를 복사하고 홈 화면 앱의 “초대 링크로 참여”에 붙여넣는다. 로그인 전 초대 화면에서도 복사할 수 있다.
- 알림 클릭은 같은 origin의 기존 창으로 이동한 뒤 focus한다. 외부 origin으로의 이동은 허용하지 않는다.
- [Chrome 내비게이션 설명](https://developer.chrome.com/docs/capabilities/pwa-navigation-management), [Apple 홈 화면 웹앱의 scope 설명](https://developer.apple.com/videos/play/wwdc2023/10120/)을 검토했다. iOS 외부 HTTPS 링크를 홈 화면 PWA로 강제 전환하는 보장된 설정은 없으므로 실제 기기 결과를 별도로 기록해야 한다.

## 검증

`npm.cmd run build`, `npm.cmd run lint`, `git diff --check` 실행. Chromium 320×568, 실제 API 형식의 네트워크 응답을 대체한 브라우저 검증 스크립트는 `artifacts/ios-review-browser.cjs`, 결과는 `artifacts/ios-review-browser-results.json`에 저장한다. 실제 결제·푸시 발송은 수행하지 않는다.

## 후속 UI 조정

- 방 만들기 안내는 날짜/이름 입력 행 아래로 이동해 입력칸을 정렬했다.
- 설정의 플랜은 현재 플랜과 변경 링크를 한 줄로 표시한다. 첫 두루마리 설정은 홈의 예약/지금 엮기 시트를 공유한다.
- 둘러보기는 큰 사진과 접는 이야기 카드로 구성하고, 장소 옆에 추가/변경 링크를 배치한다. 페이지당 6장을 스크롤한 뒤 번호로 이동한다. 13장으로 6/6/1 분할을 브라우저에서 확인했다.
- 생성 전 둘러보기 진입은 참여 완료 여부에 따라 비활성화하지 않는다. 사진 추가는 누적 플랜 한도를 적용하고 FREE 3장 완료 시 추가 진행을 막는다. 데모도 같은 한도를 적용한다.
- 320px 방 만들기의 입력칸 정렬·가로 넘침, 설정 시트, 장소 링크, FREE 한도 검증 결과: `artifacts/browse-refinement-results.json`.
