## 업로드 순서 근거

로컬 백엔드의 `PhotoUploadController.complete`는 `data.photo.status`를 반환한다. `PhotoUploadService`는 변환이 필요한 사진을 PROCESSING 상태로 두고 작업을 생성하며, `EntryService.create`는 READY가 아니면 첫 한마디를 거절한다. 따라서 complete 응답을 무조건 최종 완료로 취급하지 않도록 수정했다. 같은 complete 엔드포인트로 상태를 다시 확인하며 취소·실패·시간 초과에는 미확정 서버 사진을 정리한다.

읽은 로컬 백엔드와 배포 서버 버전이 같다고 가정하지 않는다. 최신 공개 API 명세는 `https://43-201-73-60.sslip.io/openapi/public-api.yaml`에서 내려받아 대조했다. 백엔드 파일은 수정하지 않았다.

## 후속 UI 피드백 반영

- 목록의 상태 필터를 제거하고 진행 중/완성 목록을 복원했다. 만들기는 제목 옆 작은 버튼으로 옮기고, 초대 링크 펼침 카드는 유지했다.
- 지도에서 첫 만들기 안내는 실제 가입 방이 없을 때만 표시한다. 일반 만들기는 전체 모임방 펼침 메뉴 안에 두며, 장소 없는 가입 방도 목록에 포함한다.
- 방·사진을 밀면 공유/삭제 버튼만 드러난다. 삭제는 버튼을 누른 뒤 별도 확인하며, 멤버의 방 메뉴는 삭제 대신 나가기다. 링크의 기본 드래그도 억제한다.
- 답가 목록·삭제 확인창·별도 작성 진입을 없애고 문단 재엮기로 정리했다. 서버의 기존 재엮기 API 계약과 과거 기록 자체는 삭제하지 않는다.
- 재엮기는 문단 아래 별도 버튼으로, 템플릿 변경은 하단으로 옮겼다. 첫 템플릿 화면은 선택/미리보기 탭에서 같은 선택·적용 동작을 제공한다.
- 본인 사진은 두루마리·미리보기·둘러보기·지도·꽃 사진 시트에서 ‘내가 올렸어요’로 표시한다.
- 카카오톡 공유는 초대/모으기/둘러보기/엮는 중/완성/플랜 변경/사진 상황에 맞는 제목·본문·버튼을 사용한다. 사용자가 입력한 초대 문구는 유지하며, 명시적인 링크 복사는 URL만 복사한다.
- 모두 참여 상태는 초록 배경과 체크로, 엮기 확인은 현재 플랜 카드와 원본 잠금 경고 카드로 강조했다. 작은 화면에서는 확인창 본문만 스크롤되고 확인·취소 버튼은 아래에 유지한다.
- 검증: 빌드·TypeScript·src ESLint·공백 검사. `artifacts/ui-followup-browser.cjs`에서 320×568 브라우저, 터치 이벤트, 삭제 취소 시 API 미호출, 공유 payload, 템플릿 실제 적용을 검사했다. 실기기 카카오톡 도착 화면은 별도 확인이 필요하다.

## 목록·제스처·날짜 설정 후속 개선

- 새 모임방 버튼을 검정으로 바꾸고, 심사용 데모 방 카드에도 일반 카드와 같은 11px 간격과 개별 테두리를 적용했다.
- 방 만들기는 버튼을 누르면 비어 있는 모임 이름·날짜·내 이름 바로 아래에 빨간 안내를 표시하고 첫 오류 입력칸으로 포커스를 옮긴다. 작성 중인 값과 날짜·시간은 현재 탭의 초안에 저장한다.
- 사진 스와이프는 제거하고 공유·삭제는 명시적 버튼으로 제공한다. 일반 친구 사진 둘러보기는 친구 사진만 표시하며, 내 사진은 핀 꽃의 사진 링크에서 연다.
- 방 스와이프는 손가락 이동량과 속도를 반영한다. 오른쪽은 공유, 왼쪽은 삭제/나가기 버튼을 드러낸다. 드러난 폭만큼만 해당 방향의 버튼을 잘라 보여 주고 카드 바탕은 불투명하게 유지한다. 되돌리기·바깥 누르기·Escape로 닫을 수 있고, 긴 스와이프도 삭제를 실행하지 않는다. 삭제/나가기는 별도 확인 모달을 거친다. 모달 높이를 뷰포트 안으로 제한한다.
- 엮기 예약을 방 만들기와 같은 datetime-local 입력으로 통일했다. iOS에서는 기기 기본 날짜·시간 선택기가 열린다. 방·멤버별 예약 초안은 취소/새로고침 후에도 현재 탭에서 복원하며, 실제 예약은 저장 버튼으로 확정한다.
- 핀 꽃·참여현황 제목을 굵게 하고 참여 완료 알림은 앱의 분홍/먹색 계열로 맞췄다.
- 모임방은 진행 중/완성 목록별 3개씩 페이지 이동한다. 지도 시트의 사진은 4개씩, 긴 AI 요약은 펼치기/접기로 제공한다.
- 두루마리는 기본 한 문단씩 읽기, 문단 바로가기·이전/다음 이동을 제공한다. 현재 탭에서 읽던 문단을 복원하고, 한 번에 읽기와 전체 저장도 유지한다.
- 지도 핀치는 이전/현재 두 손가락 중점을 모두 반영하고, 크기가 바뀌어도 보던 위치를 유지한다. 확대/축소·전체 보기 버튼 터치 영역, 키보드 확대/이동과 확대율 안내를 추가했다. 그림 지도에서 실제 지도로 자동 전환하는 동작은 없애고 실제 좌표로 명시적으로 전환하도록 했다.

검증: npm.cmd run build, npx.cmd eslint src, git diff --check 통과. 모의 API와 Chromium 320×568에서 artifacts/ui-refinement-browser.cjs의 11개 시나리오 통과. 실제 터치 이벤트로 방 스와이프와 두 손가락 지도 핀치를 검증했으며, 1.4배 확대 시 중점 기준 예상 이동의 오차가 3px 이내였다. 결과는 artifacts/ui-refinement-results.json에 있다. 실기기 iPhone Safari/PWA 제스처와 기본 선택창 외형, 실제 카카오 지도 SDK 전환은 별도 확인이 필요하다.

## 상태 처리 후속 수정 — 2026-11-10

- 모임방 목록 조회 실패를 실제 빈 목록과 구분한다. 최초 실패는 오류/재시도 화면으로, 재조회 실패는 기존 카드와 오류 안내로 표시한다. 방 홈 조회의 일시적 실패도 기존 카드를 유지하며, 403/404/410만 접근 불가로 제외한다. 오래된 요청이 최신 결과를 덮어쓰지 않게 한다.
- 예약 초안은 선택 당시 서버 예약과 현재 예약이 같을 때만 복원한다. 서버 예약이 바뀌면 최신 날짜를 표시한다. 저장 직전에 방을 다시 조회하고 예약 변경을 감지하면 PATCH 없이 확인을 안내한다. GET과 PATCH 사이의 동시 변경까지 원자적으로 막으려면 서버 버전/조건부 갱신 계약이 필요하다.
- 재엮기 완료 시 읽던 위치보다 변경된 문단을 우선 표시한다. 이후 사용자가 문단을 이동하는 동작은 유지한다.
- 친구 사진 목록은 처음 조회/추가 조회/갱신 시 내 사진만 있는 묶음을 자동으로 건너뛴다. 친구 사진을 찾거나 마지막 cursor에 도달하면 멈추고 반복 cursor는 오류로 처리한다.
- 이번 수정에서 실제 지도 전환과 스와이프 기능의 노출 방식은 변경하지 않았다.

검증: artifacts/state-followup-browser.cjs에서 Chromium 320×568과 모의 API로 최초/재조회 오류, 카드 유지, 예약 초안 복원 및 서버 변경 시 PATCH 미호출, 친구 사진 추가 조회, 재엮은 문단 초기/후속 선택을 검증했다. 결과는 artifacts/state-followup-results.json에 있으며 브라우저 실행 오류는 없었다.
